Start here · Your first local project

This guide is for junior developers setting up a Windows development environment for the first time. You’ll practice the workflow you’ll use when joining a project: set up your tools, get the code from GitHub, and run it on your own computer. Konek Story is the practice project.

Work through one session at a time. Run the commands in VS Code’s PowerShell terminal and check off each item once you’ve verified the result. Your progress is saved in this browser.

Session 1 tasks

Tips for this session

  • Use a Windows computer.
  • Keep the default installation options.
  • Restart VS Code after installing each tool.

1 Install Visual Studio Code

About 5–10 min
  1. Download the Windows User Installer from the VS Code Windows setup guide.
  2. Run the installer and keep the default options, including Add to PATH.
  3. Open VS Code from Start. Choose Terminal → New Terminal and select PowerShell if another shell opens.

What you should see
A terminal panel opens with a PowerShell prompt starting with PS.

Where do I open the terminal in VS Code?

Use Terminal → New Terminal in the top menu. Use the dropdown next to the + in the terminal panel to open a PowerShell terminal.

2 Install Git

About 5–10 min
  1. Download the installer for your computer from Git for Windows.
  2. Run it and keep the default option that makes Git available from the command line.
  3. Close and reopen VS Code. Open PowerShell and run the command below.
git --version

Example resultgit version 2.52.0.windows.1Your installed version may differ.

Git is not recognised in PowerShell

Close all VS Code windows, reopen VS Code, and try again in a new PowerShell terminal. If it still fails, rerun the Git installer and check that Git is available from the command line.

3 Install Node.js and npm

About 5–10 min
  1. Select Node.js 24 LTS and download the Windows installer (.msi) from Node.js downloads.
  2. Run the installer with npm and PATH enabled.
  3. Close and reopen VS Code. Open PowerShell and run each line below separately.
node --version
npm.cmd --version
Example resultsv24.21.011.19.0Node.js should start with v24. Your exact versions may differ.
PowerShell blocks npm

If npm --version reports that scripts are disabled, use npm.cmd --version. This runs the Windows npm launcher with your current PowerShell settings.

Complete all three checkpoints to finish this session.

Session 2 · Get your own copy of the project

Your goal: Open your own copy of Konek Story in VS Code and use Git to confirm you’re in the right folder.

Set up your Git name and email

Open PowerShell in VS Code. Git records this name and email on your commits. Replace both examples with your name and the email you use for GitHub. If you keep your email private, copy your GitHub-provided noreply address from your account settings. GitHub may ask you to sign in separately when you clone or push.

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

--global sets the defaults for repositories you use under your Windows account. Check that Git saved the values you intended.

git config --global --get user.name
git config --global --get user.email

What you should see: Your name appears after the first command and your email after the second.

Clone Konek Story

A repository is a project and its Git history. Cloning downloads both. Open the repository in your browser first. If GitHub asks you to sign in or you cannot see the repository, ask your mentor to confirm your account has access. Konek Story on GitHub

  1. Create a Projects folder anywhere you can write files. In VS Code choose File → Open Folder and select Projects. Open a new PowerShell terminal and check its starting folder. 
    Get-Location
    The last part of the path should be Projects.
  2. Download the repository. Git may open a browser for sign-in. Wait for the prompt to return. 
    git clone https://github.com/rxthyy/konek-story.git
    If you already have a clone, open it in VS Code, open a new terminal, and run git status there. Then go to Session 3.
  3. Move into the new folder and check what Git sees. 
    cd konek-story
git status
    Git should report your current branch. Open konek-story with File → Open Folder so the VS Code Explorer shows package.json and src. Open a new terminal there.
Quick check · What does git clone give you?

Think about what you’d need to see who changed a file before you joined the project.

Answer: A local copy of the project and its Git history. Run git log -1 --oneline inside konek-story to see the latest commit on your current branch.

Practice basic Git commands after the app runs

Start in the konek-story folder. Run these one at a time to inspect your local copy.

  • git status --short lists changed and new files. An empty result means the working tree is clean.
  • git branch --show-current prints the branch you are on.
  • git log -5 --oneline shows up to five recent commits.
  • git diff shows edits to tracked files that you have yet to stage.

1. Update your starting branch

Start on the branch you cloned and check that git status --short is empty. If it shows changes, review them with your mentor before pulling.

git pull --ff-only

git pull downloads and brings in commits from the current branch’s upstream branch. --ff-only updates your branch when Git can move it forward directly. If Git reports that the branches have diverged, pause and ask your mentor to review the branch history with you.

2. Create a practice branch

git checkout -b practice/first-commit

git checkout -b creates a branch from your current commit and switches to it. Use git branch --show-current to confirm you’re on practice/first-commit.

3. Stage and review one file

In VS Code, create git-practice.txt in the project folder, write one sentence, and save it.

git add git-practice.txt

git add stages the file’s current contents for the next commit. If you edit it again, run git add again to include the new edits.

git diff --cached

git diff --cached shows what is staged. Check that it contains only the practice file. If the terminal shows (END), press Q to exit the viewer.

4. Save a local commit

git commit -m "Add Git practice note"

git commit saves the staged changes to your local branch history. -m sets the commit message. Run git log -1 --oneline to confirm your commit appears.

5. Push to a practice remote

Use a fork or practice repository where your mentor has given you permission to push. Run git remote -v to check where origin points. Run the example only if its push URL is your approved practice repository. You can finish the exercise with a local commit if you don’t have a practice remote yet.

git push -u origin practice/first-commit

git push uploads your commits to the named remote branch. origin is the remote name, and -u sets the upstream so future git push and git pull commands on this branch know which remote branch to use.

Session 3 · Start the app

Use PowerShell inside konek-story. Confirm the terminal is in the right folder before installing anything.

Get-Location
Test-Path package.json

The path should end in konek-story and the second command should print True.

1. Install the project packages

npm.cmd ci

This installs the exact package versions recorded in package-lock.json. It also runs the project's setup scripts for icons and the mock API worker. The first install can take a few minutes. Wait for the prompt to return before continuing.

2. Start the development server

npm.cmd run dev -- --host 127.0.0.1

Keep the terminal open. When Vite prints Local, open that address in your browser. It is usually http://127.0.0.1:5173/. If Vite lists a different port, use the address it printed.

3. Stop and restart it

Click the terminal and press Ctrl+C to stop the server. If Windows asks whether to terminate the batch job, enter Y. Run the same start command again and refresh your browser. On a normal return visit, open the existing clone and run the start command. Run npm.cmd ci again after the dependency files change.

If you get stuck

PowerShell cannot find a command

Close all VS Code windows and reopen the editor. Repeat that tool's version check. For npm, use npm.cmd.

Git reports “repository not found”

Open the GitHub link in your browser and check that you are signed into the account your mentor granted access to.

npm cannot find package.json

Run Get-Location and open the konek-story folder in VS Code. Open a new terminal and repeat the folder check.

The browser cannot reach the app

Check that Vite is still running and use the exact address it printed. If installation or startup failed, bring your mentor the command you ran and the first error message.

Session 4 · Install PHP and Composer

Complete this session when you’re ready to work with PHP projects.

  1. Ask your mentor which PHP version the team's backend uses. Download that Windows build from PHP, extract it to a folder you can write to, and add the folder containing php.exe to your user Path in Windows Environment Variables. Open a fresh PowerShell window and check the version. PHP for Windows 
    php --version
  2. Composer installs packages for PHP projects. Use Composer-Setup.exe and select the php.exe you verified if prompted. Open a new PowerShell window and check Composer. Composer Windows installation 
    composer --version

Session 5 · Install Docker Desktop

Use this session to prepare for container work after running Konek Story locally.

  1. Ask your mentor or IT to confirm that your computer meets the Windows, virtualization and WSL 2 requirements. If WSL needs setup, follow Microsoft's guide with them and restart if prompted. Install WSL
  2. Download Docker Desktop for Windows, run the installer with the WSL 2 backend, then launch Docker Desktop and wait for the engine to start. Open a fresh PowerShell window and run these checks. Docker Desktop for Windows 
    docker version
docker compose version
    Docker should report both Client and Server. Compose should print its version.
